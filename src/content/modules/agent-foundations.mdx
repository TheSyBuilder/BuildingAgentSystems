<section className="control-section" aria-labelledby="control-title">
  <div className="section-intro">
    <div>
      <p className="module-kicker">Control ownership</p>
      <h2 id="control-title">Put judgment inside code.</h2>
    </div>
    <p>
      “Model-directed” should describe only the uncertain choice. Keep known
      sequence, validation, permissions, budgets, and side effects deterministic.
    </p>
  </div>

  <div className="control-board" aria-label="Deterministic and model-directed issue-triage loop">
    <div className="control-board-header" aria-hidden="true">
      <span>Stage</span>
      <span>Owner</span>
      <span>Issue-triage behavior</span>
      <span>Why this owner</span>
    </div>
    <ol>
      <li>
        <span className="control-stage">01 · Observe</span>
        <span className="owner-badge owner-code">Code</span>
        <strong>Load and validate the frozen issue.</strong>
        <p>The input shape and read boundary are known in advance.</p>
      </li>
      <li>
        <span className="control-stage">02 · Decide</span>
        <span className="owner-badge owner-model">Model</span>
        <strong>Choose which missing evidence matters next.</strong>
        <p>The best read depends on the issue’s language and current evidence.</p>
      </li>
      <li>
        <span className="control-stage">03 · Act</span>
        <span className="owner-badge owner-code">Code</span>
        <strong>Execute one allowed read tool.</strong>
        <p>Tool validation, permission checks, and timeouts are runtime work.</p>
      </li>
      <li>
        <span className="control-stage">04 · Verify</span>
        <span className="owner-badge owner-shared">Shared</span>
        <strong>Interpret the result; enforce the acceptance check.</strong>
        <p>The model reads meaning. Code checks structure, budget, and policy.</p>
      </li>
      <li>
        <span className="control-stage">05 · Stop</span>
        <span className="owner-badge owner-code">Code</span>
        <strong>Return the proposal or hand off.</strong>
        <p>A verified receipt, exceeded limit, error, or approval boundary ends the loop.</p>
      </li>
    </ol>
  </div>

  <aside className="control-rule" aria-label="Control ownership rule">
    <span>Rule of thumb</span>
    <p>
      Let the model choose where interpretation is the point. Use deterministic
      code wherever the correct behavior can be written, validated, or enforced.
    </p>
  </aside>
</section>

<section className="canvas-section" id="architecture-canvas" aria-labelledby="canvas-title">
  <div className="canvas-heading">
    <div>
      <p className="module-kicker">Textual architecture canvas · BAS-002</p>
      <h2 id="canvas-title">Make every owner visible.</h2>
    </div>
    <p>
      This filled canvas is the non-interactive reference for the builder that
      follows. If a row is unknown, keep the agent read-only or shrink the job.
    </p>
  </div>

  <div className="canvas-sheet">
    <p className="canvas-stamp">Frozen reference · issue triage · read-only</p>
    <dl>
      <div>
        <dt>Goal</dt>
        <dd>Propose one label and priority for an incoming issue, with evidence a maintainer can review.</dd>
      </div>
      <div>
        <dt>Success evidence</dt>
        <dd>Valid proposed label, stated priority, quoted issue facts, similar-issue references, and a rationale.</dd>
      </div>
      <div>
        <dt>Instructions</dt>
        <dd>Follow the triage rubric; separate fact from inference; never claim a duplicate without a cited match.</dd>
      </div>
      <div>
        <dt>Context</dt>
        <dd>Current issue, label taxonomy, severity rubric, tool definitions, and only the retrieved similar issues.</dd>
      </div>
      <div>
        <dt>Model choice</dt>
        <dd>Choose the next read, interpret ambiguous evidence, and draft the proposal.</dd>
      </div>
      <div>
        <dt>Deterministic shell</dt>
        <dd>Validate inputs and outputs, execute allowlisted reads, count steps, record results, and enforce stops.</dd>
      </div>
      <div>
        <dt>Authority</dt>
        <dd>Read the bundled snapshot and propose. Posting a comment or applying a label requires human approval.</dd>
      </div>
      <div>
        <dt>Run state</dt>
        <dd>Issue ID, gathered evidence, tool results, step count, proposed classification, and pending handoff.</dd>
      </div>
      <div>
        <dt>Persistence</dt>
        <dd>No cross-session memory yet. The completed proposal receipt can be exported; the sample snapshot stays unchanged.</dd>
      </div>
      <div>
        <dt>Stop conditions</dt>
        <dd>Verified proposal; no useful read remains; malformed or denied tool result; budget reached; or approval required.</dd>
      </div>
      <div>
        <dt>Handoff receipt</dt>
        <dd>Outcome, evidence used, uncertainty left, actions taken, actions not taken, and the exact approval request.</dd>
      </div>
    </dl>
  </div>

  <aside className="canvas-blank" aria-labelledby="blank-title">
    <div>
      <p className="module-kicker">Reader copy · blank canvas</p>
      <h3 id="blank-title">Ask before you automate.</h3>
    </div>
    <ol>
      <li><span>01</span>What observable outcome is the system responsible for?</li>
      <li><span>02</span>What evidence proves success rather than merely ending the run?</li>
      <li><span>03</span>Which choices truly require model judgment?</li>
      <li><span>04</span>Which sequence, permissions, checks, and limits stay in code?</li>
      <li><span>05</span>What context is needed now, and what state must live later?</li>
      <li><span>06</span>What stops, hands off, or requires approval?</li>
    </ol>
  </aside>
</section>
